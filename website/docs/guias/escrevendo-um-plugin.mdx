# Escrevendo um plugin

Um plugin tem três partes: o **kernel** (função pura), o **sistema** (que aplica o kernel aos frames) e o **plugin** (que registra o sistema em um stage). O exemplo abaixo inverte as cores de cada frame; é o arquivo `examples/custom_plugin.rs` do repositório, compilado no CI.

<CodeBlock language="rust" title="examples/custom_plugin.rs">{Example}</CodeBlock>

```bash
cargo run --example custom_plugin
```

## Pontos de atenção

- **Componente marcador**: `Without<InvertTag>` na query garante que cada frame seja processado uma única vez. Sem isso, o sistema inverteria o frame de novo a cada tick.
- **`#[derive(Component)]`** exige `bevy_ecs` como dependência direta do seu projeto — veja [Instalação](../primeiros-passos/instalacao.md).
- **Kernel separado**: `invert` pode ser testada sem montar um pipeline.
- **Sem sistema à mão**: quando o sistema só aplica o kernel ao frame, como aqui, `builder.add_op(Stage::Process, invert.tagged::<InvertTag>())` gera o mesmo sistema — ver [Kernels como sistemas](./kernels-como-sistemas.mdx).

## Sistemas que podem falhar

Um sistema não deve engolir um erro com `warn!`. Há dois caminhos, conforme o alcance da falha:

- retornar `Result<()>` e registrar com `fallible(sistema)`, quando o sistema inteiro falhou;
- chamar `PipelineErrors::report_frame`, quando só um frame falhou.

A reação do pipeline é a [`ErrorPolicy`](../conceitos/pipeline-e-stages.md#tratamento-de-erros).

<CodeBlock language="rust" title="examples/error_policy.rs">{ErrorExample}</CodeBlock>

```bash
cargo run --example error_policy
```

## Métodos de registro

`builder.add_system(Stage::X, sistema)` registra em qualquer stage; os métodos abaixo são atalhos. Para ordenar sistemas do mesmo stage, passe `(a, b).chain()` — ver [Visibilidade de componentes](../conceitos/pipeline-e-stages.md#visibilidade-de-componentes).

| Atalho | Stage |
|---|---|
| `add_input_system` | `Stage::Input` |
| `add_pre_process_system` | `Stage::PreProcess` |
| `add_process_system` | `Stage::Process` |
| `add_post_process_system` | `Stage::PostProcess` |
| `add_output_system` | `Stage::Output` |
| `add_cleanup_system` | `Stage::Cleanup` |
