# perceptor-core

Tipos fundamentais, sem dependência de ECS ou I/O. A crate usa `#![forbid(unsafe_code)]`.

## `Error` e `Result`

Todas as crates do Perceptor retornam `perceptor_core::Result<T>`, um alias para `Result<T, perceptor_core::Error>`.

| Variante | Quando ocorre |
|---|---|
| `BufferLength { len, channels }` | o buffer não contém um número inteiro de pixels |
| `ChannelMismatch { expected, actual }` | a operação exige um número específico de canais |
| `UnsupportedChannels { channels }` | o número de canais não tem representação no destino (ex.: formato de arquivo) |
| `NonContiguous` | o buffer não está em memória contígua em ordem de linha |
| `Decode { path, source }` | falha ao ler ou decodificar uma imagem |
| `Encode { path, source }` | falha ao codificar ou gravar uma imagem |

O enum é `#[non_exhaustive]`: um `match` fora da crate precisa de um braço `_`. `Decode` e `Encode` preservam o erro original em `source()`.

<CodeBlock language="rust" title="examples/read_frame_error.rs">{Example}</CodeBlock>

`Error` implementa `std::error::Error + Send + Sync`, então converte para `anyhow::Error` com `?` em binários.

## Formatos de pixel

O formato faz parte do tipo: uma função que recebe `&[Rgb8]` não precisa checar o número de canais em runtime.

| Tipo | Subpixel | Canais | Ordem na memória |
|---|---|---|---|
| `L8` | `u8` | 1 | `L` |
| `La8` | `u8` | 2 | `L, A` |
| `Rgb8` | `u8` | 3 | `R, G, B` |
| `Rgba8` | `u8` | 4 | `R, G, B, A` |
| `Bgr8` | `u8` | 3 | `B, G, R` |
| `L16` | `u16` | 1 | `L` |
| `LF32` | `f32` | 1 | `L` |
| `RgbF32` | `f32` | 3 | `R, G, B` |

Cada tipo é um wrapper `#[repr(transparent)]` sobre um array de subpixels, então `&[Rgb8]` e `&[u8]` descrevem a mesma memória. O trait `Pixel` expõe as conversões:

| Item | Descrição |
|---|---|
| `Pixel::CHANNELS`, `Pixel::FORMAT` | número de canais e `PixelFormat` correspondente |
| `channels()` / `channels_mut()` | canais de um pixel, na ordem da memória |
| `cast_slice` / `cast_slice_mut` | `&[Subpixel]` → `&[Self]`; erro `BufferLength` se o comprimento não for múltiplo dos canais |
| `as_subpixels` / `as_subpixels_mut` | `&[Self]` → `&[Subpixel]`; nunca falha |

<CodeBlock language="rust" title="examples/pixel_cast.rs">{PixelCast}</CodeBlock>

`PixelFormat` é o mesmo conjunto como enum de runtime (`channels()`, `sample()`, `bytes_per_pixel()`), para quando o formato só é conhecido ao decodificar um arquivo ou negociar com uma câmera. `Subpixel` é implementado apenas para `u8`, `u16` e `f32`; `Subpixel::MAX` é o branco nominal (`255`, `65535`, `1.0`).

Os casts são feitos pela crate [`bytemuck`](https://docs.rs/bytemuck), que verifica tamanho e alinhamento; `perceptor-core` continua sem nenhum `unsafe` próprio.

## `Image<P>`

Imagem dona do buffer: `width × height` pixels do formato `P`, em ordem de linha, em memória contígua que começa em um endereço múltiplo de 64 bytes (`Image::ALIGNMENT`).

| Construtor | Conteúdo |
|---|---|
| `Image::new(w, h)` | todos os subpixels em zero |
| `Image::filled(w, h, pixel)` | todos os pixels iguais |
| `Image::from_fn(w, h, \|x, y\| ...)` | valor calculado por coordenada |
| `Image::from_vec(w, h, vec)` / `from_pixels(w, h, &[P])` | cópia de pixels em ordem de linha |
| `Image::from_subpixels(w, h, &[u8])` | cópia de subpixels intercalados |

Todos retornam `Result`:

| Erro | Condição |
|---|---|
| `InvalidDimensions` | largura ou altura zero, ou tamanho em bytes que não cabe em `isize` |
| `Allocation` | o alocador não atendeu ao pedido |
| `DimensionMismatch` | quantidade de pixels diferente de `w · h` |
| `BufferLength` | (`from_subpixels`) comprimento que não é múltiplo dos canais |

| Acesso | Retorno |
|---|---|
| `width()`, `height()`, `dimensions()`, `stride()` | geometria; em `Image` o stride é igual à largura |
| `as_pixels()` / `as_pixels_mut()` | `&[P]` com todos os pixels |
| `as_subpixels()` / `as_subpixels_mut()` | `&[P::Subpixel]` intercalado |
| `as_bytes()` | `&[u8]` |
| `row(y)` / `row_mut(y)` | uma linha; pânico se `y >= height` |
| `get(x, y)` / `get_mut(x, y)` | `Option`, checando `x` e `y` separadamente |
| `image[(x, y)]` | pânico fora dos limites |
| `into_vec()` | `Vec<P>` em ordem de linha |

<CodeBlock language="rust" title="examples/image_basics.rs">{ImageBasics}</CodeBlock>

`from_vec` copia os pixels: um `Vec<P>` comum não garante alinhamento de 64 bytes, e adotá-lo quebraria a invariante.
